# dsh-plugin-workspace-discipline

[English](README.public.md) | 中文

一个给 **DeepSeek Harness（dsh）** 用的轻量本地文件整理插件。

它只给 agent 定一条规矩：**你做出来的东西都放进工作区里的项目文件夹**——不许散在根目录，不许做完了还留在临时目录里。顺带让它把可复用的产出存进共享库，并在丢掉一个项目之前把经历记下来。

- **平台**：仅限 DeepSeek Harness。这是一个 dsh 插件，在别的 harness 上不起任何作用。
- **范围**：只管文件摆放和项目卫生。不碰模型、token、网络、界面。
- **体量**：单个 `index.js`，无依赖，无构建步骤。
- **怎么约束的**：一段提示词，加一道写入守卫。详见 [它到底做了什么](#它到底做了什么) 与 [风险与局限](#风险与局限)——那道守卫是护栏，**不是安全边界**。

> 本插件主要由 AI agent 设计并编写，由人类机主下达要求。行为是多轮实机测试的结果，因此带有较明显的单机习惯。请把它当作「一个人的工具公开出来」，而不是打磨过的产品。

---

## 想法

agent 很会干活，很不会收拾。一轮会话结束，工作区里躺着一堆草稿文件、做了一半的目录，以及下次还会被重写一遍的脚本。

这个插件把「收拾」也变成工作的一部分。每轮会话都在项目文件夹里进行，而每个文件夹自己说明它的状态：

```
<workspace>/
├── C-<name>/     已完成，值得保留
├── CW-<name>/    已完成，可抛弃 —— 整个删掉没问题
├── T-<name>/     未完成，进行中
├── W-<name>/     废弃 —— 整个删掉没问题
├── tools/        可复用脚本
├── skills/       可复用技能（SKILL.md）
├── mcp/          可复用 MCP 服务器定义
└── log/          已处置项目的经历
```

两种前缀是有实际含义的：

| 前缀 | 做完了？ | 要留？ | 说明 |
|---|---|---|---|
| `C-` | 是 | 要 | 默认落点。里面不许有 `TEMP`。 |
| `CW-` | 是 | 不要 | 结果已经拿到，文件夹可以走。里面不许有 `TEMP`。 |
| `T-` | 否 | — | 进行中，可以有 `TEMP`。 |
| `W-` | 否 | 不要 | 废弃。删掉不丢东西。 |

**`CW-` 和 `W-` 是留给人的。** 模型只能建 `C-` 和 `T-`，它想新建 `CW-`/`W-` 会被拒绝——这样模型就没法悄悄把自己的活标成「可以删」。

## 它到底做了什么

三件事，由一个插件统一注册：

**1. 一段提示词。** 布局说明会被注入到**每一个模型步骤**，而不是只在会话开头注入一次。这正是它能在长会话里不让规则漂出模型视野的原因。这段文字约 2–3 KB。

**2. 一道写入守卫。** `write` 或 `edit` 执行前先检查目标路径，放错位置就拒绝，并告诉它该放哪。会拒绝的情况：

- 文件直接放在工作区根目录（少数元数据文件除外）
- 文件散在共享库根上，而不是放进某个条目文件夹
- 文件夹名不以合法前缀开头
- `C-` / `CW-` 项目里出现 `TEMP` 路径
- 新建 `CW-` 或 `W-` 文件夹
- 重写共享库的 `README.md` 时丢掉已记录的历史

**3. 一个发现工具。** `workspace_layout` 列出已有的项目文件夹和各共享库的内容，让模型接着用已有文件夹而不是另开一个，并且在写新东西之前能找到可复用的条目。

## 安装

```bash
dsh plugin --profile <profile> add <包名>
```

或者从本地目录安装（开发时就是这样）：让 agent 调用 `plugin_manager` 的 `install_bundle`，目标填包目录的绝对路径。配置档会把它记成 `link:` 依赖。

装好之后，如果配置档把 bundle 置为禁用，请启用它，然后重启 dsh，让 bundle 重新被包含。

`engines.dsh` 声明 `>=0.2.1-rc.3`。这是实测通过的版本，不是对将来版本的保证。

## 使用

不需要主动调用。插件生效后，每轮会话都按这套布局走。

如果你会话的工作目录**就是**工作区，那就完全不用配置——插件守的就是会话所在的那个目录。

如果工作区是会话目录的**上级**（比如会话从 `<workspace>/某个子目录` 开始，而项目都放在 `<workspace>` 下），就要显式指定根目录：

```yaml
- insert:
    - id: workspace-discipline
      name: 'dsh-plugin-workspace-discipline'
      config:
        roots:
          - '/你的/工作区/绝对路径'
        strict: true
```

### 配置项

| 字段 | 默认值 | 含义 |
|---|---|---|
| `roots` | `[]` | 要约束的工作区根目录。留空表示「会话自己所在的目录」。 |
| `libraries` | `['tools','skills','mcp','log']` | 哪些文件夹名算作项目旁边的共享库。 |
| `ignore` | `[]` | 根相对路径前缀，不受守卫约束，用于早于本约定的历史目录。按段匹配：`legacy` 豁免 `legacy/...`，但不豁免 `legacy2/...`。 |
| `strict` | `true` | 设为 `false` 会关掉写入守卫，但保留提示词和工具。 |

## 风险与局限

装之前先读。这些是真实代价，不是免责声明。

**每一步都要花上下文。** 提示词注入的是每个模型步骤，不是每轮会话。几 KB 的文字，而且对话被压缩时它也不会消失。长会话下来这是一笔稳定且不为零的开销。

**共享库同样吃上下文。** 攒的工具、技能、MCP 条目、日志条目越多，开工前要读的也越多。一个有五十份工具 README 的工作区，在里面干活并不便宜。插件鼓励复用，而复用是有代价的。

**它看不见 shell 写入。** 守卫检查的是带文件路径的工具调用——`write` 和 `edit`。用 shell 命令（`Set-Content`、`echo >`、构建脚本、`Copy-Item`）写出来的文件它完全看不到。在宽松沙箱下这就是一条彻底的绕过通道。请把它当成品德护栏，而不是围栏。

**它看不见改名。** 用 shell 命令给文件夹改名不会被拦，所以模型理论上可以把 `C-` 改成 `CW-`。`CW-`/`W-` 归人所有这条，是靠「新建时拒绝」实现的，不是靠改名拦截。

**历史保护是形状检查。** 对共享库 `README.md` 的重写，插件只检查标题是否还在、已有行会不会消失。它发现不了「某条记录被改写了措辞而不是被删除」，而 shell 写入完全跳过这项检查。

**它对命名很固执。** `C-`、`CW-`、`T-`、`W-` 加四个固定库名，就是它的全部方案。这套命名不合你的习惯，那这个插件就不适合你——`libraries` 可以改库名，但项目前缀是固定的。

**是一台机器的习惯。** 规则是在一个有真实项目的工作区里调出来的，所以具体，也因此有点偏。请预期需要自己调整。

## 与其它插件的关系

- **[dot-ai](https://github.com/jogelin/dot-ai)** 定义 `.ai/` 工作区约定，带记忆、任务、技能、路由和多平台适配层。那是一个框架。本插件小得多，只回答一个问题：这个文件该放哪。它没有记忆、任务、路由这些系统。
- **[cc-safety-net](https://github.com/kenryu42/cc-safety-net)** 在工具调用前拦危险命令和敏感文件访问。本插件不拦危险命令，它管的是产出放在哪里。

想要工作区框架就用 dot-ai；只想要 agent 别乱扔文件，这个工具更小。

## 卸载

禁用或移除 bundle 即可，提示词和守卫立刻消失。插件鼓励建出来的文件夹会留在磁盘上——它从不删除任何东西，对已经存在的文件也没有意见。
